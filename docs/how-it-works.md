# Как это устроено

## Участники

- **Головное устройство (ГУ)** — Android 9. Системное приложение `com.incall.interactive` отвечает за связь с приборкой.
- **Приборка** — отдельный компьютер со своей прошивкой (не Android). Приложения туда не ставятся.

Связь между ними:

1. **Управление** — TCP-сокет на порту 10001 по внутреннему USB-Ethernet (поэтому USB должен быть в режиме U)
   и CAN-свойства автомобиля (например, `AP_NAVI_STATE`).
2. **Видео** — второй экран ГУ («дисплей 1» в Android, 1920×720) физически выведен на вход приборки.
   Что нарисовано на дисплее 1, то приборка показывает, когда сама переключится на видео.

Приборку нельзя заставить показать видео — с ней можно только правильно договориться.

## Штатный обмен сообщениями (рассчитан на навигатор Amap)

1. Навигатор рассылает broadcast `AUTONAVI_STANDARD_BROADCAST_SEND` с `KEY_TYPE=10019` и `EXTRA_STATE`.
   `interactive` превращает число в статус для приборки: **12** — «навигация идёт», **4** — «навигатор в фоне».
   Без обоих приборка не открывает навигацию.
2. Водитель выбирает в меню приборки Normal Navi или En Navi — приборка шлёт ГУ запрос видео (код 1 или 3).
3. ГУ подтверждает запрос и ждёт от навигатора ответа `KEY_TYPE=10117` («нарисовал»).
4. Получив ответ, ГУ командует приборке переключиться на видео. **Без ответа 10117 приборка закрывает режим.**

Amap на машинах для России нет — шаги 1 и 4 никто не делал. Мост делает их за навигатор.

## Что делает мост ClusterBridge

- Каждые 20 секунд шлёт `EXTRA_STATE 12` и `4`.
- Подписывается на запрос видео у `interactive` (экспортированный сервис `com.incall.double.INTERACTIVE_SERVICE`,
  метод `registerNavigateCallback`) и отвечает `10117`.
- Следит за статусом приборки: **0** — без навигации, **2** — Normal Navi, **3** — En Navi.
  Из Normal в En приборка переходит без запроса видео (видео уже включено), поэтому карта едет по статусу.
- Рисует на дисплее 1 стрелку, расстояние и улицу в окне, которое приборка показывает в Normal Navi
  (квадрат 320×320: x 160–480, y 240–560 кадра 1920×720 — измерено калибровочной сеткой).
- Подписывается на системные жесты ГУ (свайп тремя пальцами) — тот же механизм, что у штатного жеста.

### Откуда берётся подсказка

| Ситуация | Источник |
|---|---|
| Яндекс свёрнут | Его уведомление: расстояние, улица и картинка стрелки (самого Яндекса) |
| Яндекс на экране ГУ | Уведомление без подсказки → служба специальных возможностей читает панель манёвра Яндекса: описание стрелки («Поверните направо»), расстояние, улицу; стрелку мост рисует сам |

Снимать экран ГУ сторонним приложениям прошивка не даёт (проекция выдаётся без копии экрана), поэтому так.

## Помощник helper.sh

Перенести окно Яндекса на дисплей 1 (`am display move-stack`) и задать ему размер (`am stack resize`) обычное
приложение не может — это команды оболочки ADB. Помощник работает с правами оболочки: читает в логе сигналы
моста `EN_MAP on/off` и переносит карту. Мост запускает его сам, подключаясь к ADB собственного ГУ по
`127.0.0.1:5555` — для этого нужен постоянный ADB по сети.

## Почему без root

Почти всё нужное есть в штатных механизмах ГУ: экспортированный сервис связи с приборкой, broadcast'ы навигации,
второй дисплей, права, которые можно выдать по ADB (`appops`, слушатель уведомлений, служба специальных
возможностей), и сама оболочка ADB. Root понадобился бы только для изменения прошивки — этого не требуется.
